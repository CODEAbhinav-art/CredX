# CredX — AI Safety & Responsible AI Document

**Product:** CredX
**Last Updated:** 2026-09-15

---

## 1. Purpose

This document records CredX's approach to responsible use of AI/ML in a credit-related context. It is intended to demonstrate to competition judges, future investors, and regulators that CredX takes AI safety seriously from the ground up.

---

## 2. What CredX Is and Is Not

| CredX IS | CredX IS NOT |
|---|---|
| An explanatory credit-health platform | A licensed credit bureau or rating agency |
| A tool providing model-derived estimates | A provider of guaranteed loan approvals |
| An educational financial-awareness product | A replacement for formal credit assessment |
| An alternative to having no credit visibility | A substitute for CIBIL or equivalent bureau |

---

## 3. Model Safety Principles

### 3.1 No Discriminatory Features

The following feature categories are explicitly excluded from the ML model:

- Age
- Gender
- Caste, religion, ethnicity
- Geographic region (proxy for socioeconomic status)
- Employer name (proxy for class)
- Marital status
- Any other protected characteristic under Indian law

**Enforcement:** The feature schema (`data/feature_schema.json`) is the single source of truth for all features used in training. Any new feature must be reviewed against this list before addition.

### 3.2 Feature Defensibility

Every feature in the model must have a defensible, documented business rationale. "Increases AUC" alone is not a sufficient reason to add a feature.

### 3.3 Model Evaluation for Fairness

Post-training, the following checks are performed:
- Score distribution is reviewed to ensure it is not bimodal in a way that discriminates against a user archetype
- Persona-based testing (A, B, C) validates that the model behaves intuitively across different financial profiles

## 4. GenAI Safety Principles

### 4.1 Role of the LLM

The LLM (Gemini Flash) plays **one role only**: explaining the ML model's output in natural language.

The LLM:
- **Does** receive: score, risk band, SHAP values, user question
- **Does not** receive: raw transaction data, PII, Aadhaar, PAN, phone numbers
- **Does not** make any credit decision
- **Does not** override or modify the ML model output
- **Does not** invent numerical scores or percentages

### 4.2 Structured Output Validation

LLM responses are validated against a Pydantic schema before being returned to the frontend. If the LLM returns a response that doesn't match the expected schema:
1. The system retries once with a more constrained prompt
2. If it still fails, the deterministic fallback is used

This prevents hallucinated data from reaching the UI.

### 4.3 Prompt Minimization

Prompts to the LLM contain only:
- The CredX score (integer)
- The risk band (string)
- The top 3 positive SHAP contributors (feature name + direction)
- The top 3 negative SHAP contributors (feature name + direction)
- The user's question (sanitized)
- A system instruction clarifying the LLM's role

Prompts never contain:
- User's name or identity
- Aadhaar / PAN / bank account numbers
- Phone numbers
- Raw transaction history
- Sensitive financial details beyond what is described above

### 4.4 Mandatory Disclaimers

The following disclaimers are displayed at all times in the UI:

> "CredX Score is an alternative credit health indicator. It is not a CIBIL score and does not represent a formal credit assessment."

> "Estimated Approval Likelihood is a model-derived estimate only. It does not constitute a guaranteed loan approval or rejection."

> "AI explanations are generated by a language model to help you understand the scoring model's output. They are not financial or legal advice."

> "Simulated scores are estimates only. Actual credit decisions are made by lenders using their own criteria."

### 4.5 Simulator Safety

The what-if simulator:
- Re-runs the actual ML model with modified inputs
- Does NOT allow the LLM to invent the numerical result
- Labels all simulated outputs as "Estimated" or "Simulated"
- Does not guarantee that a real-world action will produce the simulated change

## 5. Data Privacy

- No real user PII is stored or processed
- The MVP uses only synthetic data
- No data is sent to third parties other than the Gemini API
- The Gemini API receives only the minimal structured context described in Section 4.3
- API keys are stored in environment variables, never committed to source control

---

## 6. Regulatory Awareness

CredX is aware of the following regulatory context (though it is not directly regulated as an MVP):

- **RBI Guidelines on Digital Lending:** CredX does not originate loans or disburse funds
- **PDPB / DPDPA (India):** No personal data is collected or stored
- **IRDAI / SEBI:** Not applicable (no insurance or securities products)
- **Algorithmic fairness:** No discriminatory features; fairness testing performed

---

## 7. Limitations Disclosure

The following limitations are disclosed in the product README and UI:

1. The model is trained on **synthetic data** and may not perfectly reflect real-world credit risk distributions
2. The CredX score is an **estimate** and should not be used as the sole basis for any financial decision
3. The AI Copilot is a **language model** and may occasionally produce imperfect explanations
4. The product is an **MVP** and has not been audited by a financial regulator
